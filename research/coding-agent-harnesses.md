## What vendors publish as best practice

Sources are first-party pages fetched in this run. Dates are shown where the page gives one.

**Anthropic**
- Claude Code best practices (code.claude.com/docs/en/best-practices, fetched 2026-10-13, no date): give Claude a check it can run; explore, plan, then code; keep CLAUDE.md short and prune it; use hooks for actions that must happen every time; use subagents to keep research out of the main context; add an adversarial review step in a fresh subagent; use `/clear` between unrelated tasks; after two failed corrections, start over with a better prompt; the context window is the main constraint.
- "Effective harnesses for long-running agents" (anthropic.com/engineering/effective-harnesses-for-long-running-agents, published 2025-11-26): a JSON feature list with a `passes` status per feature; a progress file plus git history; an init script; an initializer session, then coding sessions that work one feature at a time; end-to-end testing with browser automation; "It is unacceptable to remove or edit tests". The page states an open question: whether one general agent works better than specialised testing or QA agents.
- "Building effective agents" (anthropic.com/research/building-effective-agents, published 2024-12-19): find the simplest solution and add complexity only when it demonstrably improves outcomes; orchestrator-workers for subtasks that cannot be predicted in advance; measure and iterate; test in sandboxed environments with guardrails; design tools with the care given to human interfaces.

**OpenAI**
- Codex best practices (learn.chatgpt.com/guides/best-practices, fetched 2026-10-13, no date): tests, lint and type checks; `/review` before accepting a diff; a "Done when" condition; a short AGENTS.md, updated after repeated mistakes and layered by directory; plan first on complex tasks; worktrees for parallel work; start with default permissions and loosen them only for trusted repos.
- Long-running work (learn.chatgpt.com/docs/long-running-work.md, fetched 2026-10-13): a goal has Outcome, Constraints and Verification; `/plan` interviews the user first.
- "Harness engineering: leveraging Codex in an agent-first world" (openai.com/index/harness-engineering/; primary returned 403, so unverified). InfoQ (https://www.infoq.com/news/2026/02/openai-harness-engineering-codex, dated 2026-02-21 on the page, fetched 2026-10-13) reports that the repository is the system of record, that AGENTS.md is kept short, and that linters and structural tests enforce architecture. InfoQ's own framing is separated from OpenAI's claims in its text.

**Cognition (Devin)**
- Devin docs (fetched 2026-10-13): make tasks easy to verify, for example by checking that CI passes; Devin Memory is on by default; the docs index lists Playbooks and an AGENTS.md page. No written best-practice guide was fetched.

**Google (Jules) and Cursor**
- Jules docs (fetched 2026-10-13): read AGENTS.md from the repo root; review the plan before changes are made.
- Cursor docs (fetched 2026-10-13): cloud agents produce screenshots, videos and logs as artifacts of their work.

**Where the sources agree**
1. Give the agent a runnable check: tests, build, lint, screenshots or a "done when" condition (Anthropic, OpenAI, Devin, Jules, Cursor).
2. Keep a short, checked-in instruction file and update it when the agent repeats a mistake. Anthropic uses CLAUDE.md and OpenAI uses AGENTS.md; Jules reads AGENTS.md, and Claude Code reads AGENTS.md when no CLAUDE.md is present.
3. Plan before implementing complex work, with a human approving or shaping the plan (Anthropic plan mode, OpenAI `/plan`, Jules plan approval, Cline Plan mode).
4. Use a separate review pass, ideally in a fresh context (Anthropic's adversarial review subagent, Jules Critic, Devin Review, OpenAI `/review`).
5. Isolate parallel work in separate worktrees, branches or VMs (Anthropic, OpenAI, Cursor, Copilot).
6. Sandbox commands and limit permissions, with approvals tight by default (Anthropic, OpenAI, Devin, Cline).
7. Use deterministic hooks or CI for rules that must always hold (Anthropic hooks; OpenAI's CI linters and structural tests).

**Where they conflict or differ**
1. Memory: Anthropic's auto memory (on by default in local sessions) and Devin Memory (on by default) both let the agent write its own notes. Anthropic's CLAUDE.md guidance (under 200 lines, pruned when things go wrong) and OpenAI's guidance (add rules only after a repeated mistake) are human-curated. Anthropic's memory page says both of its memory files are context, not enforced configuration, and points to a PreToolUse hook for enforcement.
2. Subagents and teams: Anthropic presents subagents as its default delegation tool and agent teams as experimental and off by default, warning that teams add token cost and suit only independent parallel work. OpenAI's subagents page says current releases enable subagent workflows by default. Devin labels its custom subagents experimental. Cline's page describes Multi-Agent Teams without a status.
3. Benchmarks: OpenAI says it no longer evaluates SWE-bench Verified because of contamination and recommends SWE-bench Pro (search results only; primary unfetched). Anthropic's Opus 4.7 footnotes say memorization screens flag a subset of problems in the Verified, Pro and Multilingual evals; its figures are in images that were not readable in this run.
4. Permission defaults: Anthropic's best-practices page says auto mode is the built-in starting mode for interactive terminal and VS Code sessions from v2.1.283. Anthropic's permissions page says `bypassPermissions` belongs in isolated environments such as containers or VMs. OpenAI's best practices say to start with default permissions and loosen them only for trusted repos. Cline requires approval for every file edit and terminal command by default; OpenCode's `plan` agent denies edits.
5. Reviewer independence: Anthropic recommends a fresh-context model that tries to refute the work. OpenAI's auto-review reviews only approval requests, not code quality, and cannot widen the sandbox.

## Relevance to this project

Facts and gaps only. Project context: a model-agnostic factory; a human-written plan; a plan-challenge skill; separate roles for test writing (TDD), testing (runs tests, cannot edit), implementation (production code only) and review; a deterministic controller that enforces gates, sandboxing, append-only audit and gated merge. Motivating failures: duplicated render paths (copying kept tests green), no cross-task structural memory, and no engineer in the loop.

**Overlaps**
- Role separation by tool list: Claude Code subagents take `tools`, `disallowedTools` and `permissionMode`; Codex custom agents take `sandbox_mode`; OpenCode's `plan` agent is read-only; Devin's `subagent_explore` cannot edit. These are harness-level equivalents of the Testing role's "cannot edit" constraint.
- Path-scoped rules: Claude Code Read and Edit deny rules can target paths. The permissions page says they apply to Claude's built-in file tools, to file commands recognised in Bash, and to Bash redirections. It says they do not apply to arbitrary subprocesses that open files themselves, such as a Python or Node script. For OS-level enforcement against every process, it points to the sandbox (https://code.claude.com/docs/en/permissions, fetched 2026-10-13).
- Gates that can block: Claude Code hooks (TaskCompleted, SubagentStop, Stop, TeammateIdle; exit 2 blocks or continues) and Codex hooks (PreToolUse, Stop) can block or continue. Claude Code hooks cannot override deny rules. Codex non-managed hooks need trust review by hash.
- Sandboxing: Claude Code and Codex both use Seatbelt on macOS and bubblewrap on Linux. Claude Code's sandbox is off by default and `/sandbox` turns it on. Codex's sandboxing page calls `workspace-write` the default low-friction mode for local work, and `codex exec` defaults to read-only. Devin's CLI refuses to start if sandbox setup fails.
- Replayable orchestration: Claude Code dynamic workflows return saved results for completed agents on relaunch, and make `Date.now()` and `Math.random()` throw inside the script so that relaunches repeat the same agent calls. This is the only replay mechanism found in the fetched pages.
- Persistent memory: Claude Code auto memory (a per-project `MEMORY.md` index with topic files; first 200 lines or 25 KB loaded), Claude Code subagent memory, Devin Memory (Git-backed, pruned by Dreaming), Codex AGENTS.md (32 KiB cap), and AGENTS.md reading in Claude Code and Jules. Anthropic's memory page says these are context, not enforced configuration. None is described as a structural code index. The best-practices page mentions code-intelligence plugins for symbol navigation and automatic error detection after edits.
- Open-source options with permissive licences: Codex CLI (Apache-2.0), OpenHands SDK (MIT), mini-SWE-agent (MIT), Aider (Apache-2.0), Cline (Apache-2.0), Gemini CLI (Apache-2.0), OpenCode (MIT) and goose (Apache-2.0). Claude Code is under proprietary terms.
- Model-agnostic designs: mini-SWE-agent's Bash Only track runs every model through the same bash-only agent (swebench.com/verified); the OpenHands SDK is multi-LLM (arXiv 2511.03690). Claude Code and Codex CLI are built around their vendors' models. The headless docs name Amazon Bedrock, Google Cloud's Agent Platform and Microsoft Foundry as provider credential sources.

**Gaps**
- No fetched harness describes an append-only audit log as a feature. Claude Code subagent transcripts are deleted after `cleanupPeriodDays` (30 days by default) (sub-agents page). Export or telemetry options were not checked.
- No fetched harness describes a merge gate controlled outside the agent. Copilot opens one PR per task; Devin Review can apply fixes; Jules CI Fixer pushes fixes to its own PRs; Codex auto-review routes approvals to a reviewer agent.
- Claude Code's agent teams are experimental and do not restore in-process teammates on `/resume`. They allow no nested teams and one team per session. Teammates inherit the lead's permission mode; per-teammate modes cannot be set at spawn time, but can be changed after spawning. Teammate permission prompts appear in the lead session.
- No harness fetched describes a plan-challenge step or an independent plan reviewer before implementation. Plan approval is a human or lead-agent step: Claude Code approves a teammate's plan in the lead session as soon as the request arrives, without the lead reviewing it; Jules shows a plan for approval before changes.
- Duplicated code is not addressed by any fetched harness doc. Anthropic's best-practices page suggests pointing Claude at existing patterns in the codebase; it does not describe duplicate detection.
- Benchmarks do not isolate the harness. Search results (not fetched) report that Anthropic's Opus 4.6 system card shows GPT-5.2-Codex at 57.5% on the Terminus-2 harness and 64.7% on the Codex CLI harness; unverified. The SWE-bench Bash Only track fixes the scaffold, so it measures models. No fetched source gives a harness-only comparison on identical models.
- Vendor-reported 2026 figures are unverified or secondary. The primary OpenAI posts and the official SWE-bench leaderboard entries could not be read in this run.
