### 2c. Secondary claims

- Blog posts headline an "18% productivity boost" from METR's 2026 numbers. The -18% estimate has a CI from -38% to +9%, and METR's post calls the data "very weak evidence".
- GitClear's 2022 to 2025 productivity page (gitclear.com/research/ai_tool_impact_on_developer_productive_output_from_2022_to_2025) returned no figures. No GitClear productivity numbers are used here.

Gap: the controlled experiments above did not measure PR acceptance, revert rate, or review burden. For those, only the field studies in 2b are available, and they use different definitions.

## Relevance to this project

Facts and gaps only. Each item maps to the known failures: duplication kept green by tests; no cross-task structural memory; no engineer in the loop.

**Duplication and copy-over-reuse**
- GitClear (vendor; AI-attribution method not stated on page): copy/paste share rose from 9.4% (2022) to 15.7% (H1 2026); moved code fell from 21% (2022) to 3.8% (YTD 2026). Its 2025 report says copy/paste lines exceeded moved lines in 2024 for the first time in its dataset. These measure commits in general, not agent-written code specifically.
- "More Code, Less Reuse" (MSR 2026; one repo, crewAI, 617 PRs for redundancy): agent PRs show redundancy about 1.87x human (0.2867 vs 0.1532). The paper's own threats section says the redundancy analysis covered one repo. Reviewers expressed "more neutral or positive emotions" toward the more redundant agent PRs (no numbers).
- FSE 2025 clone study: commercial code generators produced Type-1 and Type-2 clones at rates up to 7.50%. Sample size not on page.
- Agentic refactoring (Java, AIDev): agents target refactoring in 26.1% of commits (Horikawa et al.), but design and implementation smell counts did not fall (77.50 to 77.50; 355.50 to 356.00). Cursor was the only agent with a significant smell increase in Ottenhof et al.
- No primary study found measures duplicated code blocks in agent PRs against the human baseline over time.

**Shared structural memory across tasks**
- Context files (Gloaguen et al., ETH Zurich): LLM-generated and developer-written files did not significantly change resolution rate on SWE-bench Lite or CTXbench (Python only). They raised inference cost by 20 to 23%. Lulla et al. report lower runtime and output tokens on 124 PRs in 10 repos.
- Architecture and design: c-CRAB found the lowest pass rates for documentation and design, and maintainability ranged 7.9% to 27.0%.
- Accumulation over time: the Cursor adoption study (CMU, 806 repos, staggered DiD) describes a "transient" velocity increase and "persistent" increases in static analysis warnings and code complexity (abstract). Warnings and complexity are described as "major factors driving long-term velocity slowdown" in the panel GMM.
- Agent-authored PRs can be larger; "higher issue counts are primarily driven by larger PRs" (Cynthia et al.). The METR transcript note estimates a 1.5x to 13x time-savings factor on Claude Code tasks for 7 METR staff, which it calls a soft upper bound.
- Tufano et al. (controlled, 29 experts, 2024-era LLM): reviewers started from the LLM review focused on flagged lines, found more low-severity issues, and did not find more high-severity ones.
- No primary study of cross-task or repository-level structural memory for agents was found.

**Human involvement and review**
- Measured speed and perception diverge. METR 2025: 19% slower with AI, while developers estimated about 20% faster afterward. METR 2026: its data is an "unreliable signal"; the design is being changed because developers declined the no-AI condition.
- Google (96 engineers, 2024 tools): about 21% faster, CI includes zero; code quality "not explored".
- Echoes of AI (151 participants): Phase 2 showed no significant difference in completion time or code quality; the Bayesian CodeHealth interval excludes zero by a small margin.
- Revert rates: Codex 6.1% vs human 11.5% (OR 0.50); Devin 14.5% (OR 1.31); the other three agents not different from humans per the search summary (Kraishan, single-author preprint).
- Among merged agent PRs, 15.4% needed explicit reviewer involvement; among rejected agent PRs, 35.7% reflected clear agentic failure (Peralta et al.).
- Agent-only review (CRA-only PRs) merged at 45.20% vs 68.37% for human-only PRs in the AIDev sample (Chowdhury et al.).
- Agent PRs with security content merge at 61.50% vs 77.33% for non-security agent PRs; median review latency is 3.92 h vs 0.11 h (Siddiq et al.).
- No primary study measured how many engineers reviewed agent-written PRs, or the review load a team absorbs.

**Tests, specs and gates**
- Tests in the prompt: direction only (Mathews and Nagappan), with no percentages on the fetched page.
- Static-analysis loops: Blyth et al. report large reductions in flagged issues over ten iterations for one model and one benchmark. No primary study found tests agents running their own analyzers on an engine codebase.
- Post-merge quality: Cynthia et al. find code smells dominate agent bug-fix PRs and that merge success does not track post-merge quality. Observational.
- Spec-first test generation at Google: +9.8 percentage points in bug detection (p=0.0352). Test generation, not code generation.
- No primary study found tests a test-first agent workflow against test-last on code quality.
- No primary study measured whether passing tests detect duplicated code in agent PRs.

**C++, engine and performance**
- MISRA C++: none of five chat models produced MISRA-compliant code despite clear prompts (Umer, 2025).
- GameEngineBench (UE5 C++): strongest configuration pass@1 55.5%; 31 of 110 tasks unsolved by all configurations. No maintainability or performance measure.
- CraftBench-UE: C++ completion exceeded Blueprint by 30.0 and 42.9 points.
- Energy study (2502.02412): models much less successful on C++ than Python or Java. LLM-HPC++ reports strong syntax and scalability for ChatGPT-4 and -5 without numbers.
- No primary study found measures sanitizer, undefined-behaviour, or ABI defects in agent-written engine code at repository scale.

**Gaps relevant to the project**
- No controlled study of agent-written code over repeated tasks in one codebase, which is the setting of the duplicated-render-path failure.
- No primary study of linter or gate-in-loop agents on code-quality outcomes at engine scale.
- No primary study of specs versus no specs for code-quality outcomes with agents.
- No measured human review burden per agent PR.
- Most vendor-reported quality numbers (GitClear, CodeRabbit) have no published methodology in the fetched text.
